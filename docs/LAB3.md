# Лабораторна робота 3 — PostgreSQL, JPA та Liquibase

## Що реалізовано

- PostgreSQL у Docker Compose; схема описана в `LAB3_DATABASE_DESIGN.md`.
- П'ять послідовних changeset Liquibase: таблиці/sequence, індекси, унікальність
  категорій, унікальність назви товару в категорії та початкові категорії.
- Чотири JPA-сутності та репозиторії: Category, Product, Order, OrderItem.
- CRUD сервісів категорій, товарів і замовлень. Оновлення замовлення — зміна статусу;
  довільне переписування історичних позицій не додавалося.
- Читання в read-only транзакціях; зміни — у звичайних транзакціях.
- Ціни та назви покупок зберігаються незалежно від подальших змін каталогу.
- Product API зберігає UUID, валідацію, формат сторінок та попередній порядок UUID.
  Новий HTTP 409 означає дублі назви або заборонене видалення зв'язаних даних.
- Схему змінює Liquibase; Hibernate запускається з `ddl-auto=validate`.
- Інтеграційні перевірки з реальним PostgreSQL через Testcontainers, зокрема
  `@DataJpaTest` із частковим контекстом і окремі перевірки повного API.
- Поріг JaCoCo: не менше 80% рядків у всьому застосунку; для кожного сервісу
  додатково не менше 80% рядків і гілок. Класи не виключалися для підвищення відсотка.

Корзик залишається доменною моделлю: його збереження не вимагає ця лабораторна.
Нові HTTP-контролери для категорій/замовлень не додавалися: CRUD доступний через
сервіси й репозиторії та перевірений інтеграційними тестами.

## Локальний запуск

Docker Desktop має працювати. Java 17 або новіша, Gradle встановлювати окремо не потрібно.

1. Підготувати `.env` за `.env.example`, задати власний POSTGRES_PASSWORD.
   Якщо `.env` уже є, зберегти його: поточне локальне налаштування вже підготовлено.
   Справжній `.env` виключено з Git.
2. Запустити PostgreSQL:

   ```sh
   docker compose -p cosmo-cats-lab3 up -d
   ```

   Контейнер використовує порт 5433 на localhost, щоб не заважати вже встановленій
   локальній PostgreSQL на 5432. Дані зберігаються в окремому Docker volume.
3. У тій самій папці завантажити локальні змінні та запустити застосунок:

   ```sh
   set -a
   source .env
   set +a
   DB_URL="jdbc:postgresql://localhost:${POSTGRES_PORT}/${POSTGRES_DB}" \
   DB_USERNAME="$POSTGRES_USER" DB_PASSWORD="$POSTGRES_PASSWORD" ./gradlew bootRun
   ```

4. Product API працює на `http://localhost:8080/api/products`.

Liquibase застосовує міграції під час старту. Повторний запуск не повинен
створювати дублікати. Початкові категорії зберігають UUID першої лабораторної.

Для зупинки PostgreSQL без втрати даних:

```sh
docker compose -p cosmo-cats-lab3 stop
```

Не використовувати `down -v`, якщо дані потрібно зберегти: ця команда видаляє volume.

## Тести та звіти

На поточному Mac встановлено Docker Engine 20.10 із API 1.41. Для нього потрібен
локальний параметр сумісності:

```sh
DOCKER_API_VERSION=1.41 ./gradlew clean build
```

На сучасному Docker без такого обмеження та в GitHub Actions:

```sh
./gradlew clean build
```

Тести самостійно запускають окремі тимчасові контейнери PostgreSQL. Їм не потрібні
локальний Compose-контейнер чи пароль із `.env`; робоча база не очищується тестами.

- `build/reports/tests/test/index.html` — результати тестів.
- `build/reports/coverage/index.html` — покриття HTML.
- `build/reports/coverage/coverage.xml` — покриття для автоматичних перевірок.

Є перевірки CRUD після очищення JPA-контексту, sequence, індексів і changelog,
обмежень даних, унікальності, зовнішніх ключів, RESTRICT/CASCADE, історичних цін,
а також реального rollback замовлення після помилки в другій позиції.
Mockito-тести ProductService виконуються окремо від контейнерних перевірок.

## Додаткові пункти

Складена унікальність `(category_id, product_name)` реалізована й перевіряється БД.
Natural ID та projection-звіт популярності не входять до поточної реалізації.
JPQL використовується для збереження сумісного порядку UUID, але сам по собі
цей запит не замінює бонусне завдання про звіт популярності.
